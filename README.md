# Статическая климатическая база

Карта читает климат только из `data/climate/<ISO3>.json`. Во время работы страницы внешние климатические API не вызываются.

## Сборка данных

Требуется Node.js 18+.

```bash
npm run build:climate
```

Дополнительные npm-зависимости сборщику больше не нужны.

Скрипт один раз скачивает:

- Natural Earth — страны и значимые города;
- WMO Climatological Standard Normals 1991–2020 (`TAVG`, `TMIN`, `TMAX`, min24 composites);
- CRU TS 4.09 — официальные ASCII `.dat.gz` за 1991–2000, 2001–2010 и 2011–2020 для `TMP`, `TMN`, `TMX`.

CRU-файлы читаются потоково. Для городов без близкой полной WMO-станции скрипт выбирает ближайшую сухопутную ячейку сетки CRU 0.5° и сам считает 12 среднемесячных норм за 1991–2020.

После выполнения создаются файлы `data/climate/AAA.json`, `data/climate/ALB.json`, ..., а также `manifest.json`.

`KAZ.json` не перезаписывается: для Казахстана сохраняется уже вручную проверенный набор Казгидромет/WMO/CRU.

Кэш исходных файлов находится в `.cache/climate-build`. Старые файлы `cru-mean.nc`, `cru-min.nc`, `cru-max.nc` от предыдущего генератора можно удалить — новая версия их не использует.

После сборки страница доступна по адресу:

`http://localhost:3000`

## Быстрая клиентская загрузка

`index.html` содержит разметку; CSS и JS находятся в `assets/`. Климат Казахстана
загружается параллельно со стилем карты, резервный модуль — только при ошибке JSON.
Запросы климата и геометрии повторно используются в пределах открытой страницы;
ошибки не кешируются. MapLibre закреплён на версии 6.8.0 без CDN-редиректа диапазона версий.

Браузер читает `data/geography/index.json` (названия и прямоугольники полигонов),
затем геометрию выбранной страны. Геолокация проверяет точные полигоны только
для подходящих прямоугольников. Координаты, острова и отверстия исходного
Natural Earth 1:10m сохранены без упрощения.

Географические файлы уже включены в репозиторий. Для их обновления после
обновления `.cache/climate-build/ne-countries.geojson` сборщиком климата:

```bash
npm run build:geography
```

Источник: [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/), public domain;
исходный файл — `ne_10m_admin_0_countries.geojson` из `nvkelso/natural-earth-vector`.

Для публикации:

```bash
npm ci
npm test
npm run build
```

Публикуйте содержимое `dist/`. После установки зависимостей через `npm ci` сборка работает без сети.
JavaScript минифицируется esbuild (ES modules, ES2020) до вычисления хешей:
это относится и к основному модулю, и к лениво загружаемому резервному модулю.
CSS также минифицируется esbuild до хеширования и сжатия Brotli/gzip
(целевые браузеры: Chrome 100, Firefox 100, Safari 15.4 и новее).
Исходники в `assets/` остаются читаемыми. Сборка создаёт имена CSS/JS с хешем
содержимого, минифицирует JSON и подготавливает `.br`/`.gz`.
`dist/_headers` задаёт годовое immutable-кеширование ресурсов с хешами и
перепроверку HTML/данных на Netlify/Cloudflare Pages. На другом хостинге настройте
эквивалентный `Cache-Control`. Сервер должен включать Brotli/gzip либо выдавать
подготовленные варианты по `Accept-Encoding` с корректными `Content-Encoding`
и `Vary: Accept-Encoding`; одно наличие `.br`/`.gz` не включает сжатие.
Развёртывайте релиз атомарно; сохраняйте старые файлы с хешами для уже открытых вкладок.

География для начального Казахстана: примерно 340 КБ вместо 13,29 МБ
(индекс + граница, без сжатия), около 99 КБ с Brotli. Размеры не включают
MapLibre, стиль, тайлы и климат. Их скорость зависит от CDN и сети.

Подходы: [раннее обнаружение критических ресурсов](https://web.dev/articles/preload-critical-assets)
и [версионирование ресурсов для HTTP-кеша](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching).
